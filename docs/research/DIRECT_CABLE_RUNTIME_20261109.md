# 直接从线内运行：实现与验收边界

## 当前选择

mini 从线内只读卷打开应用，由 mini CPU 执行。不复制到 Applications，不安装服务，不注册登录项。第一次打开和文件入口授权遵循系统确认流程。系统缓存、临时接收文件和最终粘贴文件可能写入磁盘，不能称为绝对零写盘。

产品不依赖 DevSpace、远程终端、ToDesk、macOS 共享、Wi-Fi 或蓝牙。本轮没有访问或执行 mini 终端命令。

## 数据与启动路径

1. Book 控制器先启动已保留的输入捕获、原生触点和边缘返回。
2. 独立文件 CDC 接口向 V467 PSRAM 上传只读程序镜像。此时剪贴板文件引擎尚未占用该接口。
3. 固件校验镜像后提供只读 MSC 卷，USB HID 始终保留。mini 使用跨屏鼠标打开卷内的 `WiredKVM 临时连接.app`。
4. Book 便携剪贴板组件与 mini 组件建立会话。图片、文件和文件夹正文走二进制 Bulk，HID 仅承载有界控制与元数据。
5. 文件粘贴使用接收端自己的本地文件入口提供 Finder 进度。它不启用 macOS 共享；跨机器正文只经过 USB。

两端本机复制走系统原有路径。跨机提交绑定剪贴板版本；新的本机复制使旧提交失效。取消使旧传输代次失效，新粘贴立即申请新会话。

便携组件不接管滚动或四指注入；这些继续由已验收的 native-v2 固件处理。当前实验身份仍是 `05ac:0265`，不是可直接商用的身份授权。

## 程序盘与存储

- 当前完整 arm64/x86_64 便携程序：3,342,784 字节，已链接 Rust 文件夹引擎。
- 当前完整 WKDUAL01 镜像：3,407,872 字节；4 MiB 区域剩余 786,432 字节。
- 镜像已经过挂载、文件哈希、执行权限及严格签名校验。开发版是 ad-hoc 签名，未做 Developer ID 公证。
- 这个容量不包含 Windows 程序。加入 Windows 或改变签名资源后须重新核算。
- V467 开发板没有已确认的外部 NOR。本轮使用其 8 MiB PSRAM 的前 4 MiB；断电后由 Book 重新上传。
- V407 没有此 PSRAM。量产候选须用外部 Flash 保存镜像；本轮不做 PCB、不更改成本承诺。
- 程序从卷内运行期间必须保留来源卷；不执行旧安装器的自动推出。

## RAM 装载协议

`native/cable-image` 为无堆分配的 no_std Rust 状态机。`native/cable-loader` 是 Book 装载工具；C 仅封装 IOKit、TTY 和 PSRAM 寄存器。

- 上传走 USB1 的文件 CDC，不占键鼠控制 CDC、目标 HID、触点端点或文件桥队列。
- 每格 512 字节，最多 476 字节正文，逐格 CRC32；带非零会话、顺序偏移、总长度和整体校验值。
- 有查询、开始、正文、完成、取消操作；上传端最多使用 16 格窗口。
- 固件限制镜像为 4 MiB，写入后读回；验证整个上传、WKDUAL01 头和内部文件系统镜像校验后才发布。
- 未完成、断开、越界、旧会话、损坏或 RAM 错误不能发布半成品。数据重发只允许幂等重复最后一格。
- 已发布镜像在本次供电期间不可覆盖或取消，防止破坏 mini 正在执行的来源卷。重新连接可复用完全相同的镜像。
- 只接 Book 也能装载，不能用旧文件桥“两端在线”的条件限制程序盘启动。
- USB2 重连清除普通文件的残留分格状态，但不能取消正在进行的独立启动镜像上传。

## 当前可复用的候选

本地构建结果不进入源码仓库。构建脚本均使用新目录，不替换当前可用控制程序。

- 目标应用：`build/portable-direct-cable-20261109-portal-v5/`
- 程序盘：`build/portable-media-20261109-portal-v5/`
- Book 协调器与固定哈希配置：`build/portable-book-20261109-diag-v8/`
- RAM 程序盘固件：`experiments/mt2-petros-profile/candidate-ram-setup-20261109-power-v3/`
- 原生输入已验收固件继续保留在 `candidate-native-v2-final-20261109/`。

Book 协调器先等待输入捕获就绪，再异步上传程序盘；上传失败保留输入并重试。装载工具退出并释放文件 CDC 后才启动剪贴板组件。组件与装载工具使用同一独占文件锁。剪贴板子进程退出后可重试，不能删除仍被输入控制器使用的私有 socket 目录。

Rust 监督服务已支持可选的便携协调器及固定哈希配置；保留旧 input-only 模式。当前 v8 在 Book 临时运行，尚未安装为 LaunchAgent。原 LaunchAgent 仅在本次会话中 bootout，plist、旧二进制及授权保留；不能称为新版登录自启已通过。

## 验证要求

离线证据在 `results/portable-direct-cable-20261109/`。它们覆盖模拟双向文件、图片、文件夹、取消重试、本机复制优先、原生输入共存和实际主循环调度。模拟耗时不能作为真实 USB 速度。

当前实机：PSRAM 供电修正版的刷写/独立读回通过。当前 v5 只读程序盘上传 8.228 秒；用户已在 mini 直接打开卷内应用，双向新文字、两台内部新文字复制粘贴、键鼠、双指、四指及自动返回均确认正常。

文件入口的 `/var` 与 `/private/var` 别名问题已修复：必须在挂载前用 realpath 固定本地目录。隔离实测挂载入口可用，v5 已应用到两端。原来的 mini→Book 首轮粘贴出现 Finder 100004、Book 文件 0 字节，明确判为失败。切换 Book v8 诊断版后重试，完整接收 8,388,608 字节，整体 SHA-256 和 Book 原文件/回传文件均为 `1b56cc59b9da209542f3bda071bb65f1bddca2c7ee9f5aeac90e4cd7b5716b4e`，实现一次真实往返内容校验。该次 USB 正文约 10.303 秒、约 0.81 MB/s；这不满足“高速已交付”的结论。首轮错误的根因尚未确定，不能把诊断版重试通过写成根因修复。

当前证据：`autostart-trial-v8/return-integrity-check.json`、`clipboard-metadata-after-retry.log`；它们位于上述 results 目录，未公开提交。图片、多文件/文件夹、物理取消、新粘贴时延、饱和输入延迟和真实重启尚待验收。
实机仍须逐项完成：

1. DBG 核对芯片 `0x46740011`、UID `ad21ad506c54c6c6`、调试器序列号 `A47C8F062A1A`，备份并逐字节读回新固件。
2. 恢复 Book→USB1、mini→USB2 后，先确认键鼠、拖选、双指、四指和自动边缘返回。
3. 测量 RAM 镜像上传耗时，确认只读卷可读、直接启动，无复制安装、服务或登录项。
4. 在两台机器各做本机新文字复制粘贴；再做跨机两个方向的新文字、图片、单文件、多文件、文件夹和空目录。
5. 大文件立即粘贴时出现进度，完成后校验 SHA-256；连续传输时测键鼠与返回延迟。
6. 取消后马上发起新粘贴；中途本机复制、拔线、组件退出及重连均不得提交旧内容或失去本机控制。
7. 最后再接入 Book 自动服务，验证登录后、插拔后和控制程序退出后的恢复。

这些实机项目未完成，目标不能标记为完成。

`scripts/flash_portable_candidate.py --describe` 仅检查文件与哈希；`--flash --expected-current <已验收版本>` 是显式 DBG 刷写入口，必须明确指定当前固件。它要求只有指定 DBG，先核对芯片身份，再备份完整 576 KiB、确认原可用固件前缀、刷写及独立读回。刷写失败会尝试完整备份回退。它不更改 Book 自动服务，也不启动 mini 程序。

参考：[沁恒 PSRAM 应用说明](https://github.com/openwch/ch32_application_notes/blob/main/zh/AN36000/AN36000.md)、[沁恒 SDK 的 200 MHz PSRAM 示例](https://github.com/openwch/ch32v407_ch32v467/tree/main/EVT/EXAM/PSRAM/PSRAM/User)。
