# 程序盘 PSRAM 故障恢复

## 问题与证据边界

程序盘使用 CH32V467 的易失性 PSRAM。旧固件在写后读回不一致时锁定 `ready=false`，拒绝发布不完整镜像。这项完整性保护是必要的，但 Book 每次重试只重新查询、上传，不能解除锁定，导致一直不出现程序盘。

本次修复的是**故障后的自动恢复路径**。首次读写错误的根因仍未确定。时序、供电、低功耗状态和读缓存仍需实机排查。

## 恢复契约

- 原 WKIM 格仍为 512 字节，新增 `RECOVER=6`。请求的会话、偏移、总长度、校验值必须全零，正文必须为空，格 CRC 必须有效；只有 USB1 的程序装载协议接收。
- Rust `Upload` 在内存不可用检查之前处理恢复。已封存镜像和活动上传均返回 `Busy`，不得调用内存恢复；健康且未占用的内存直接返回 `Accepted`，不做初始化。
- C 适配层仅允许未发布、已锁定故障的内存恢复。每次固件启动最多两次，计数不随 USB 重连、上传会话结束或 Book 装载进程重启清零；MCU 复位或断电重启会重新计数。进行中的重复请求不消耗次数。
- 恢复分步进行：重置并配置 PSRAM 控制器、等待稳定、读写模式命令、模式读回、14 个分散位置的探测。每次主循环最多一次阶段操作或一块 512 字节探测。忙位每轮只读一次，等待上限 20 ms，按无符号差值处理计时回绕。
- 恢复服务在键鼠、触点和文件/控制端点服务之后执行。不重置 USB，不改系统或 USB 时钟，不重新启动输入捕获，也不触碰两台机器的系统剪贴板。
- `RECOVER` 的 `Busy` 仅表示申请进行中。只有后续 `QUERY` 返回 `Accepted` 才能重新上传。失败或次数耗尽仍不出盘。

固定 16 字诊断布局保留，版本提升到 3；`stage=5` 表示恢复中，`stage=6` 表示恢复次数耗尽。它不开放任意内存读取。旧版诊断不支持恢复时，Book 明确报告需要更新固件，不盲发复位命令。

## Book 装载与完整性

Book 先排空已提交窗口的回复，再处理同会话 `Storage` 失败或初始 `Unavailable`。诊断确认支持恢复后申请恢复，并以有界间隔查询；最多等待 3 秒，单次装载最多申请两次恢复。

恢复成功后使用新会话，从偏移零完整重传。错误会话、错误确认偏移、CRC/长度错误、普通 I/O 失败和已封存的不同镜像不能触发自动重置。装载和剪贴板仍使用同一独占文件端口；失败不停止独立输入程序。

两道原有校验继续保留：

1. 每格 CRC、每次 PSRAM 写后读回、完整接收流与镜像头校验；通过后 `Upload` 才封存。
2. MSC 每轮最多读取 512 字节，校验物理存储的整个文件系统镜像 CRC；通过后才向电脑提供介质。

封存即进入不可重置保护，即使后续 MSC 物理 CRC 不通过也不能在线覆盖。这种封存后失败仍需单独诊断；当前自动恢复只覆盖封存之前的故障。不能以跳过校验或提供半成品来“恢复出盘”。

恢复次数耗尽后，不再执行内存初始化。原 Book 协调器仍会周期性发起轻量发现和状态查询；这不补充固件的恢复次数。

## 离线验证

```sh
python3 tests/test_cable_runtime.py
python3 tests/test_psram_recovery_integration.py
python3 experiments/mt2-petros-profile/test_live_touch.py --native-format --ram-setup --bulk-batch --bulk-profile --bulk-continuous-out --bulk-probe
python3 tests/test_flash_portable_candidate.py
```

测试覆盖真实 C 适配层的故障锁定、分步恢复、超时及计时回绕、次数耗尽、已发布保护；Rust 状态机覆盖非法请求、活动上传、旧会话和封存保护；Book 装载使用隔离 socket 覆盖故障后完整重传和旧固件兼容。联合模型连接真实 Rust 协议、C PSRAM 适配层和 MSC 验证，不以始终可用的假内存掩盖锁定故障。

离线结果：Upload 协议 8 项、Book 装载 socket 14 项、PSRAM/MSC/输入桥联合场景 3 项通过；生成固件主循环的双向 Bulk 压力 1,000 轮及 11 项刷写准入/回退测试通过。C 模型的 AddressSanitizer、UndefinedBehaviorSanitizer 检查通过。真实 RISC-V 固件交叉编译和 Book 装载工具 release 构建通过；固件镜像为 90,448 字节。

这些测试不访问真实 USB、个人文件或系统剪贴板，也不代表实机 PSRAM 时序、供电或输入延迟已经通过。

## 实机验收

2026 年 11 月 20 日，在 CH32V467 开发板上配套更新固件与 Book 装载器。更新前备份整片 Flash 和 Book 装载器配置，更新后独立读回校验固件。

- 冷启动先接 USB1 到 Book，约 3 秒后接 USB2 到 mini。两端各接一次，mini 自动出现「WiredKVM」盘，无需再次断电重插。
- Book 上传 3,960,832 字节用时约 10.3 秒。该计时从上传阶段取得。
- 用户确认键鼠、双指／四指手势及左边缘自动返回正常。
- 本轮没有触发 PSRAM 校验故障。故障后的自动恢复已有离线验证，实机故障恢复、两端独立拔插和长期重复装载仍待验证。

更换程序盘前，先完全退出线内程序并安全推出来源卷。
