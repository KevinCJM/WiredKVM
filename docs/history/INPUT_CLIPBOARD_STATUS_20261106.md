## 后续验收顺序与边界

1. 先在隔离候选中验证普通绝对指针与多触点驱动共存。单口测试只接 USB2→Book，避免占用三个 Book 接口；没有 `AbsolutePointer` 属性本身不能判定定位失败，必须测真实坐标。
2. 两指短滑、反向、结束/取消与四指动作分别实测。保留普通鼠标路径和来源区分。
3. 对双向文字、图片、文件、多文件、文件夹逐类验收。文件核对哈希；目录核对树及逐文件内容。不能从单文件成功外推目录成功。
4. 在持续文件流量下同时测键鼠、自动返回、取消后新粘贴和两台机器内部复制粘贴。先响应粘贴并显示进度，不能要求用户等待传完才按粘贴。

所有候选继续保留已核实回退版本；当前控制恢复不等于这三项已经完成。

## 本轮单口探针结果：禁止部署

- 026b 的 Logical collection 候选已离线构建；相对 0269 二进制仅 3 字节变化。没有新的实机定位结果。
- 为减少占用 Book 接口，新增隔离的 Rust 单口状态机及 macOS 验收工具。只允许五个固定坐标、零按钮/滚轮，带 nonce、序号、5 秒不续租期限及 USB 完成状态。
- 026c 草稿的 7 项 profile 测试、6 项 Rust 状态测试通过；主机工具 15 项离线测试通过。这些测试不等于驱动或真实 USB 验证。
- 独立审查发现 P1：探针取消时关闭并重开 EP82，会重置 DATA toggle，且没有可靠清除旧硬件完成事件。它可能影响后续普通 HID 或错误确认新探针完成。当前 USB mock 不能证明该操作安全。
- 因此最终候选 `candidate-stage1-single-port-v3-20261106/profile.json` 明确为 `NOT_READY_NOT_FLASHED`、`deployable: false`。macOS 工具硬编码禁止 `--execute`，在读取设备或 flash proof 之前拒绝执行，不能仅靠绑定固件哈希放行。
- 根任务复核候选的全部 29 项输入哈希、二进制哈希，以及本轮前后生产源码哈希一致。本轮未刷板或停止当前控制；三项用户功能仍未验收完成。

后续必须先修正并验证 USB 取消与完成事件归属，再开放单口定位测试。不能将此草稿当作可供用户试用的妙控板固件。
