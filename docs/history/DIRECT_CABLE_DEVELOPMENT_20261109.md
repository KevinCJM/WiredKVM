# 线内便携候选开发记录

用户最新选择允许 mini 执行线内程序，但不安装、不设置持久服务。开始改功能前，原代码与 README 已提交为 `7f09bef` 并推送到公开仓库 `KevinCJM/WiredKVM`。

本批候选没有刷板、退出当前控制器、改变自动服务或执行 mini 命令。Book 只读重新发现 `1a86:4070` 的控制口；调试器当前没有连接。

## 修正的问题

- 便携发现仍仅匹配旧目标身份 `1a86:4071`。增加当前 native-v2 的 `05ac:0265`，同时约束私有 usage、厂家、原型序列号及接口，避免匹配普通 Apple 妙控板。
- `WK_TREE` 未链接到便携构建，且启用后发现 Finder 树目录分支的条件编译语法错误。修正并链接 Rust 树引擎。
- 便携组件原先会开启旧滚动/手势注入。关闭该路径，保留已验收的硬件 native-v2 输入。
- 原生控制 CLI 排斥触点与剪贴板同时运行。仅放开有界剪贴板通道，继续排除交换盘与旧安装盘自动化。
- 包装工具会生成空 FinderInfo。源应用验签通过不足以证明盘内可启动；只清理新镜像内该属性，再重新只读挂载验签。
- 新启动上传不能受普通文件桥“两端在线”的条件限制；已发布的程序镜像不能在运行时覆盖。
- RAM 程序上传和剪贴板文件引擎必须按顺序交接独立 CDC，且使用独占文件锁。
- 捕获器就绪后才装载程序盘，装载失败保留输入；组件启动失败不能删除控制器仍绑定的私有 socket 目录。
- 自检新增的目录比较最初按 URL 表示比较，因尾部分隔符不同触发断言；用文件路径比较后通过。
- Cargo 只经 rustc 临时追加 staticlib 会向新依赖传 rmeta，导致链接失败。改成独立生成的 staticlib wrapper，保留旧 MT2 crate 的构建方式。

## 离线证据

证据目录：`results/portable-direct-cable-20261109/`。构建缓存及运行证据未进入公开 Git。

- 完整 arm64/x86_64 便携应用 3,342,112 字节；包检查 5/5。
- 最终只读程序镜像 3,405,824 字节，在 4 MiB 中剩余 788,480 字节；重新挂载后文件哈希、执行权限及严格签名通过。
- 双向各 33,570,435 字节的多根文件夹流；444 个文件哈希一致，3991 次模拟 HID 探测零失败。
- 文字与单文件提前粘贴、本机新复制优先、双向约 2.58 MB 图片、文件夹与空目录、取消后重试通过。
- 280 轮取消模拟通过；新传输首格最慢模拟时间约 73 ms，不是真实 USB 时延。
- 原生控制与剪贴板共存的 11 项回归通过。输入捕获回归 4 项沙箱内通过、3 项因系统 XPC 中断；同一失败的 3 项在沙箱外通过，不能把最初失败算作成功。
- Rust RAM 装载核心 4 项、装载端分片确认/旧会话 2 项，以及保留触点 crate 的回归通过。
- 真实生成 main.c、C USB 边界与 Rust 引擎的联调通过：1000 轮持续双向 Bulk；分片程序上传交错触点、键盘和文件流；只接 Book 仍可接收启动数据。
- Book 协调器解析、私有目录保留、非阻塞控制写入及进度状态自检通过。
- 新 RAM 固件 83,200 字节，SHA-256 `dde0403eccbade5d6a032dab4659170d8e468393a84d392cc7596c33bffed9e4`；全部记录的构建输入哈希与当前文件一致。

未完成：物理 PSRAM 初始化、真实上传及启动耗时、mini 从线内启动、真实跨机复制粘贴、物理饱和传输时输入时延、自动服务升级。旧固件与当前输入服务仍保留为可用回退。
