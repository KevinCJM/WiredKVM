# WiredKVM Mac clipboard companion

Native macOS companion for the ESP32-S3 vendor HID clipboard profile. It uses the
cable and the macOS pasteboard. It does not mount an exchange disk, use networking,
run scripts through the keyboard, install a daemon, or request Accessibility.
The target companion must be launched by the user; macOS security confirmations
are not bypassed. This is a prototype, not a signed/notarized commercial installer.

If opened from `/Volumes/WiredKVM Setup/`, the app verifies its bundle identity
and code signature, copies itself into `~/Applications/WiredKVM Companion.app`,
verifies the copy and relaunches that local copy before opening USB or the normal
pasteboard. It atomically creates a new destination and never overwrites an unknown
or different existing app. An identical executable/version is reused. Different
versions and failures show a visible dialog; this first installer does not upgrade
an existing different version. It adds no login item or privileged background job.

## Build and run

```sh
swiftc -parse-as-library -O -framework AppKit -framework IOKit \
  host/clipboard/*.swift -o build/wiredkvm-companion
build/wiredkvm-companion --self-test

# Book: native controller owns COM and creates this private Unix socket.
build/wiredkvm-companion --role host --socket /absolute/private/directory/clipboard.sock --headless

# Target Mac: default role, menu-bar status and Quit; no main window.
build/wiredkvm-companion --role target
```

The target matches VID `0x303A`, PID `0x700C`, primary UsagePage `0xFF60`,
Usage `0x61`, manufacturer `WiredKVM Prototype`, serial `Prototype-DoNotShip`.
It opens only that vendor interface without seizing it. Keyboard and mouse HID
interfaces remain owned by the operating system. A shipped product needs its own
assigned USB identity; these filters must change with its firmware.

## Supported content and user-visible limits

- Plain Unicode text, PNG (or a copied TIFF converted to PNG), and one regular file.
- At most **1 MiB of content per copy** in this first version. Images additionally
  have at most 16 megapixels and a maximum side of 8192 pixels.
- Files preserve the exact data-fork bytes and Unicode filename. Directories,
  symlinks, resource forks, file promises, multiple files, rich-text formatting,
  and file metadata/permissions are not transported. Unsupported copies report an
  error and cannot authorize a cross-computer paste.
- Received files are verified and atomically committed under
  `~/Library/Application Support/WiredKVM/Received/<unique-id>/<filename>` before
  their file URL is placed on the pasteboard. They are retained for subsequent
  Finder pastes; this version does not automatically delete received files.
- New copies synchronize only while connected. Launch/reconnect does not transmit
  the clipboard's previous contents. Local clipboard changes win over an incoming
  transfer. Simultaneous copies may both be refused; repeat the intended copy.
- Large items take measurable time over UART/HID. If transfer is incomplete,
  cross-computer Cmd-V is blocked and the user repeats it when the status says
  complete. The app never queues a delayed paste into a later focus/window.

## Host command contract

stdin is UTF-8 lines; stdout contains only these replies. Status/errors go to stderr
as `WKCLIP_STATUS STARTED|READY|DISCONNECTED|TRANSFER|ERROR ...`.

```
COPY OUT <copyNonce> [sourcePasteboardChangeCount]
COPY IN <copyNonce>
PASTE OUT <copyNonce>.<requestNonce>
PASTE IN <copyNonce>.<requestNonce>
CANCEL <copyNonce>

WKCLIP_COPY ARMED <copyNonce>
WKCLIP_PASTE READY|BLOCK <copyNonce>.<requestNonce>
```

`OUT` means Book copied for target paste; `IN` means target copied for Book paste.
Nonces are positive decimal counters generated by the capture process. For local
copy, capture reads the pasteboard change count before allowing native Cmd-C and
provides it as the optional fourth field; even if the companion receives the
command after the clipboard changes, the resulting snapshot belongs to this copy.
For target copy, capture waits for ARMED before forwarding Cmd-C: ARMED is emitted
after the target has accepted the arm message. The three-field local copy form is
also supported and arms before the caller releases Cmd-C.

ARMED preserves ordinary local copy if disconnected or a remote arm fails; it does
**not** mean transfer will succeed. Such nonces remain BLOCK. Capture must send
CANCEL if its arm deadline expires or the operation is superseded. Cmd-X must not
reuse a preceding copy nonce: cross-machine cut semantics are not implemented.

READY requires the exact latest copy's snapshot, SHA verification and application
to the destination pasteboard. OUT also sends a fresh reliable `check` message:
the target checks the applied nonce and its current pasteboard revision immediately
before acknowledging. IN checks Book's current revision locally. The caller must
match the full request token, enforce its own short deadline, and invalidate a
pending paste after a focus/cursor/keyboard change. A final target application
changing its clipboard after that check remains an OS-level concurrency boundary;
the cable cannot make arbitrary application clipboard access atomic with Cmd-V.

## Wire protocol

The host socket is same-UID, in an owned `0700` directory with socket mode `0600`.
It carries consecutive **64-byte reports**, with no length prefix or report ID.
The target sends exactly those bytes with IOHIDDeviceSetReport(Output, reportID=0)
and receives them on the dedicated Input report callback. No other HID usages are
opened or synthesized by the companion.

| Offset | Size | Field |
| --- | --- | --- |
| 0 | 4 | ASCII `WKC1` (wire version 1) |
| 4 | 1 | HELLO=1, HELLO_ACK=2, DATA=3, ACK=4, ABORT=5, PING=6, PONG=7 |
| 5 | 1 | DATA BEGIN=1 / END=2; ACK rejection=128 |
| 6 | 2 | Payload length, little endian, 0–40 |
| 8 | 8 | Sender session; ACK/ABORT refer to acknowledged transfer's sender session |
| 16 | 4 | Sequence number within transfer, little endian, starts at 0 |
| 20 | 4 | Transfer identifier, little endian, nonzero for DATA |
| 24 | 40 | Payload, zero padded |

Four reports may be in flight; receiver ACKs cumulatively. Out-of-order payloads
are not applied. After 200 ms the sender retransmits its window. At most 15 retries
without forward progress are allowed. Complete messages are bounded to 1,500,000
bytes; content is bounded separately. The final ACK means the application accepted
the full message, not merely that bytes arrived. Duplicate final DATA is ACKed
without applying the clipboard twice.

HELLO uses fresh random session nonces; HELLO_ACK echoes the initiator nonce and
carries the peer nonce. Changed/retired sessions, stale transfers and cancelled
transfers cannot resume. Heartbeats run every 500 ms; three seconds without a peer
discards transactions/readiness. Native and firmware must separately flush their
bounded transport queues on disconnect. A peer change retires its previous session
so delayed UART HELLO/ACK bytes cannot restore it.

Each application message is `SHA256(JSON) || JSON`. JSON v1 includes `kind`,
`nonce`, optional `name`, `size`, lowercase `sha256`, and base64 `body`. Content
kinds are `text`, `png`, `file`; bounded empty-body control kinds are `arm`,
`cancel`, `check`. The outer digest covers metadata and bytes; the inner digest
identifies the exact content. This is corruption detection, not encryption or
authentication against malicious USB hardware.

## Safe tests

`--self-test` uses deterministic in-memory transports, randomly named **private**
NSPasteboard instances and unique temporary fixtures; it never obtains
NSPasteboard.general or opens USB/serial devices. It checks packet framing,
checksums, packet loss/duplication/reordering, lost final ACK, rejection, disconnect,
retired-session replay, Unicode/file integrity, resource-fork/symlink rejection,
local-copy precedence, arm/paste nonce gating, echo suppression and competing
copies. The macOS pasteboard service must be available to the test process; an
execution sandbox that blocks that service must be lifted for this isolated test.
No installed target application or real hardware is exercised by these tests.
