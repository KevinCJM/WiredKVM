# WiredKVM PCBA 需求规格书

更新：2026-11-17。本文整理用户已确认的设计要求及原因；仅作为后续设计输入，本次不实施原理图、PCB 布局布线或生产下单。

## 1. 产品形态与成本

| 要求 | 原因及验收依据 |
| --- | --- |
| 单层 PCB，即一层铜；不得自行改成双层或多层板 | 控制成本与复杂度。单层铜不等于单面贴装；最终以制造层叠文件核对。若布线、回流或信号质量不满足，先说明冲突，由用户决定取舍。 |
| 普通 U 盘大小，主控侧直接插入电脑 | 避免开发板体积及多余连接。长宽厚、壳体和连接器突出量尚未冻结，不能自行声称满足某个毫米尺寸。需机械图确认遮挡、承力及相邻接口可用性。 |
| USB1 为 USB-C 公头，USB2 为 USB-C 母头 | 公头插主控，母头通过数据线接被控。两口角色固定，正反插均应正常。产品不是两台电脑之间的无源直连线。 |
| 元器件总数不超过当前 Petros CH32V467WEU6 开发板 | 减少物料、贴装和故障点。冻结 BOM 前先按同一口径统计开发板与候选板：含 IC、阻容、保护件、连接器等实际装配件；当前没有已核定的总数。 |
| 量产每块低于 ¥25；打样每块低于 ¥100，争取低于 ¥50 | 预算是目标，不是已有报价。核算需列采购数量、含税与供料条件、PCB、全部器件、贴装、烧录测试和损耗，不能只报主芯片价格。 |
| 仅保留功能必需器件，不配置无线、网口及开发板式大排针 | 产品只使用有线 USB。调试和生产测试优先保留可接触焊盘；不能为减少数量而删除必要的供电、保护或恢复功能。 |

当前未承诺“单层、尺寸、器件数量、成本及高速信号”已同时满足。旧文档中的 USB 3 数据桥、双 Hub、RP2350 或多层板备选方案不作为现行要求。

## 2. 芯片、存储与程序盘

- **CH32V407 为量产候选；CH32V467WEU6 为开发验证平台。** 必须冻结完整料号、封装、可用引脚和两个独立 USB 设备接口；开发板通过不等于 CH32V407 量产板通过。
- 沿用双 USB 有线桥接方向，分别连接两台电脑，保留键鼠／触点与 Bulk 正文的独立端点及有界队列。不得让文件正文绕经低速串口或旧 HID 小包。
- 被控端程序直接从线内只读程序盘启动，在被控电脑 CPU、内存中临时运行；不复制到应用目录、不安装后台服务、不设登录启动项。首次启动和系统权限仍遵循系统流程。
- 当前 V467 原型由主控装载程序盘到易失 PSRAM；断电不保留盘内容。不得把此能力当成 CH32V407 已具备相同存储，也不得把 PSRAM 当作非易失存储。
- CH32V407 方案必须单独核算固件、签名程序包、文件系统和缓冲区容量，说明程序盘由何种存储提供、如何装载和更新。若要求断电保留，需落实非易失存储及其成本和器件数；不默认更换量产芯片或扩大预算。
- 程序盘必须完整校验后发布。未发布盘的恢复不能阻塞输入；正在提供线内程序的来源盘不能被复位或覆盖。参见 [PSRAM 恢复边界](../docs/research/PSRAM_RECOVERY.md)。该修复仅有离线验证，不代表新板实机验收。

## 3. 供电、连接与恢复

详细约束以 [USB 供电与热插拔要求](USB_POWER_AND_HOTPLUG_REQUIREMENTS.md) 为准：

- **只有 USB1 给整板供电。** USB2 保留数据地及高阻 VBUS 检测，其 VBUS 不给整板供电，不得回灌 USB1；两侧 VBUS、CC 不能直接跨接。
- 先插被控机、后插主控机，或相反顺序，均自动建立连接；只重插任意一端不需重新插另一端、按 RESET 或手动重开主控程序。
- 主控登录后等待硬件；控制程序退出后再次插入，或电脑重启并登录后，应在已有授权有效时自动恢复。锁屏、休眠、断线时释放输入，解锁或唤醒后重新建立安全的控制状态。
- 调试接口不得旁路 USB1 独供要求。供电检测、上电时序、浪涌、保护及 USB 描述符声明均需在具体电路上核对。

当前开发板的供电与插入顺序限制留给量产板解决；不能以“按指定顺序能工作”作为新板验收通过。

## 4. 必须保留的功能

| 功能 | 要求与原因 |
| --- | --- |
| 键鼠与拖选 | 保留移动、点击、按住拖动、组合键及可靠释放；区分主控鼠标和妙控板输入。文件传输、程序盘装载或错误恢复不能卡住输入。 |
| 妙控板 | 在当前受支持的 macOS 组合保留双指平滑滚动、与主控一致的方向和四指操作；不以普通滚轮事件替代全部触点语义。其他系统需要独立适配验收。 |
| 自动边缘返回 | 从 Book 边缘进入 mini、从 mini 边缘返回均可靠；断线或锁屏后不能留下键鼠分离控制或按键卡住。 |
| 两台机器内部复制粘贴 | 各自原生复制、剪切、粘贴立即执行，不等待 USB；本机新复制优先，迟到跨机结果不得覆盖它。 |
| 双向跨机剪贴板 | 支持文字、图片、多格式项目、文件、多文件与文件夹；以系统剪贴板和版本事务判断，不按 Warp、微信等应用名称分支。 |
| 图片及文件正文 | 使用 Bulk 二进制；禁止图片正文走旧 HID 小包或 JSON/Base64。保留同一项目的可用文字及富文本。现有大小与项目数量限制见 [剪贴板状态与多格式方案](../docs/research/CLIPBOARD_STATE_V2.md)，不能误用旧图片 1 MiB 限制。 |
| 取消及新粘贴 | 取消旧事务后及时停传，新粘贴不得排队等待旧传输；断线、焦点或本机版本变化后，拒绝旧结果回放。记录停传和新请求响应耗时。 |

键鼠基础控制不能依赖被控端临时程序先启动。跨机剪贴板需要该程序接入被控系统；不得宣称完全由硬件读取系统剪贴板。产品不依赖 Wi-Fi、蓝牙、macOS 共享服务或远程控制软件；当前不宣称 Windows 已实现。

## 5. 性能要求与测量方法

- 目标是接近当前所选硬件的**实际有效上限**。接口标称位率、单端内存读写或短暂峰值不能替代端到端文件速度。
- 分别测主控↔硬件、被控↔硬件，以及双向桥接；使用相同数据规模、同一计时口径，校验接收数据。以相应方向各阶段的最慢实测值作为上限参考，解释端到端的差额。
- 文件主体保持流式传输，优先使用硬件 DMA、流水线和有界缓冲；减少额外复制、忙等、逐小包往返及人为延时。协议、操作系统和存储仍参与传输，不能承诺“代码完全不参与”或零开销。
- 在持续传输中同时检查键鼠、双指／四指、拖选和自动返回，比较空载与负载下的延迟、卡顿及丢事件，不能靠让输入失效取得速度。
- 图片需同时记录支持大小、进度首次显示时间和完整粘贴时间；文件记录端到端完成时间及有效吞吐。出现进度不等于正文成功，更不等于达到高速要求。

当前未冻结新的吞吐、延迟、取消时限或图片完成时间数值，不恢复无法核实的历史阈值。后续放行前须把测量条件、目标值和实测结果填齐；尚未完成的上限测试不能标为达标。

## 6. 新板验收与放行

| 验收项 | 通过条件 |
| --- | --- |
| 机械、层数、器件及成本 | 制造资料为单层铜；机械尺寸经确认；完整 BOM 不超过同口径开发板数量；报价满足预算及供料条件。 |
| 电气与 USB | 测量确认 USB1 独供、两端不回灌；正反插、两种插入顺序及两端独立拔插都正常；两个 USB 接口可同时工作。 |
| 程序盘 | 完整校验后出现；断电重装载和校验失败有明确状态及有界恢复；替换前退出线内进程并安全推出。不能以盘出现代替程序可运行。 |
| 基础交互 | 键鼠、组合键、拖选、双指／四指及自动返回逐项通过；锁屏和断线后释放输入，不能把键盘留在主控密码框而鼠标仍控制被控机。 |
| 数据完整性 | 双向验证文字、图片本体、图片文件、多文件、文件夹、空文件及空目录；文件逐项比大小和 SHA-256，图片能正常显示。 |
| 持续与故障负载 | 验证 GB 级文件、连续复制、取消、新粘贴、中途断线、进程退出及重连；全过程检查输入和两机本机复制粘贴，残缺文件不得当成功。 |
| 自动恢复 | 分别验证主控真实重启并登录、控制进程退出、休眠唤醒、锁屏解锁及独立拔插；主控自动恢复和被控临时程序的启动权限分别记录。 |
| 性能 | 保存单端及桥接上限、真实文件吞吐、图片完成时间和负载输入延迟；达到冻结目标并解释差额后才通过。 |

CH32V467 的既有原型结果只作为功能参考。CH32V407 的存储方案、单层高速走线与回流、电源保护、温升和制造可行性仍需独立评审及样机验证。本文不授权画板、打样或采购。
