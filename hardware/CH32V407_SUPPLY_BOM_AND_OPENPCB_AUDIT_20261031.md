## 3. 单芯片技术审计

审计原厂仓库 commit：`de8b9431e2c2f862d067a77d44859aee9e12e1d3`。

[双 Device 桥示例](https://github.com/openwch/ch32v407_ch32v467/blob/de8b9431e2c2f862d067a77d44859aee9e12e1d3/EVT/EXAM/USBHS/Dual_device/cdc_transfer/src/main.c)同时打开两路 HS Device，并转发两侧缓冲。两台电脑都做 Host，不直接短接它们的数据线。无需 Wi-Fi、蓝牙、Hub 或外置 USB PHY。仍是 **USB 2.0 HS**，不是 USB 3。

### 资源与数据路径

逻辑路径：主控 C 公头 → USBHS1 Device → 有限内存队列 → USBHS2 Device → C 母座及数据线 → 被控电脑。

- 文件使用专用 Bulk IN/OUT；输入、松键、心跳、返回确认使用独立 Interrupt 端点和队列。不要把键鼠排在文件字节流后面。
- 当前 `firmware/main/usb_hid.c:50`、`:59`、`:95` 将相对键鼠与绝对鼠标分接口，必须保留。另给控制状态、Bulk 文件和只读安装 MSC 分配端点。候选可占 EP1–EP5；USBHS1 驱动实际限制为 **8 个端点编号含 EP0**，不能误用通用头文件的 16 槽数组当硬件能力。[驱动头文件](https://github.com/openwch/ch32v407_ch32v467/blob/de8b9431e2c2f862d067a77d44859aee9e12e1d3/EVT/EXAM/USBHS/Dual_device/cdc_transfer/usb_driver/port/usbhs1_dcp.h)
- 内存预算可先留每方向 8×4 KiB，共 64 KiB；输入/控制 8 KiB；USB 状态、栈及其余应用 64 KiB，总计约 136 KiB。它是预算，需编译映射和 DMA 可达性验证，并保持所选 SRAM 配置；不是内存占用实测。
- 原厂示例是每侧 8×512 B 队列，满时 NAK。扩展 DMA 批次前须确认硬件传输长度、完成回调和缓冲所有权；USB 单个 HS Bulk 包仍最多 512 B。
- 举例，两路每毫秒各 64 B 输入/状态仅约 128 kB/s 有效载荷。带宽占用小，但**不能由带宽比例推出鼠标延迟**。20 MB/s 文件流若逐 512 B 中断转发，两端合计约 7.8 万次包完成/秒，CPU/中断调度必须实测。

### 不能原样使用的原厂逻辑

| 发现 | 影响及必须处理的条件 |
|---|---|
| `usbhs1_dcp.c:147`、USBHS2 同样在复位中断调用 `Delay_Ms(10)` | 一端复位可能阻塞另一端服务。改成有截止时间的复位状态机，不能简单删除等待而破坏协议时序 |
| `usbhs1_dcp.c:254`，USBHS2 同样在 disable 时关闭公共 `RCC_USBHSPLLON` | 一端关闭会影响共用时钟。需要双端时钟引用计数和分端口恢复 |
| `_enable` 等待 PLL 就绪没有超时 | 增加启动截止时间和本机控制恢复，不无限等待 |
| 控制请求路径打印日志；默认输出 `printf`，调试 `_write` 逐字等待 USART 发送完成 | 初始化为 115200 波特。100 字节串口输出约 8.7 ms 线时，可能超过延迟预算。生产输入/USB 中断禁用同步日志，改限量异步日志 |
| `usbd_upload()` 在端点忙时直接返回，成功只表示提交 DMA | 非阻塞基础可保留；必须等真正 IN 完成才发“已送达”确认，不在排队时确认边缘返回 |

源码：[USBHS1](https://github.com/openwch/ch32v407_ch32v467/blob/de8b9431e2c2f862d067a77d44859aee9e12e1d3/EVT/EXAM/USBHS/Dual_device/cdc_transfer/usb_driver/port/usbhs1_dcp.c)、[USBHS2](https://github.com/openwch/ch32v407_ch32v467/blob/de8b9431e2c2f862d067a77d44859aee9e12e1d3/EVT/EXAM/USBHS/Dual_device/cdc_transfer/usb_driver/port/usbhs2_dcp.c)、[设备核心](https://github.com/openwch/ch32v407_ch32v467/blob/de8b9431e2c2f862d067a77d44859aee9e12e1d3/EVT/EXAM/USBHS/Dual_device/cdc_transfer/usb_driver/src/usbd_driver_core.c)、[串口输出](https://github.com/openwch/ch32v407_ch32v467/blob/de8b9431e2c2f862d067a77d44859aee9e12e1d3/EVT/EXAM/SRC/Debug/debug.c)。原始文件内容保存于本轮 JSON。

单颗 MCU 仍共享 CPU、电源和时钟。可设计为文件拥塞只触发反压，不阻塞 HID；不能承诺 MCU 崩溃或电源故障时键鼠仍完全不受影响。

### 保留现有功能的门槛

1. HID 先就绪，不等待安装盘、Companion 或文件服务；安装资源直接从本地 Flash 读。
2. 主控输入线程、被控 HID 和自动返回状态机独立于文件读写、哈希、取消和慢磁盘处理。松键/松鼠标不可丢；鼠标移动可合并。
3. `native/wiredkvm.cpp:694` 附近的送达确认/返回语义及 100 ms 心跳、250 ms 失联处理须迁移和回归，不靠改变用户两台 Mac 的快捷键设置解决问题。
4. 两台机器本机复制粘贴仍即时走本机剪贴板；跨机才使用 USB。保留 Finder 原生进度；接收数据不自动覆盖用户刚在本机复制的内容。
5. 当前 `WKClipboardContent.swift:60`、`WKFilePortal.swift:48` 仍限制 1 MiB。大文件必须改为 64 位长度、流式分块、端到端哈希、临时文件完成后提交和取消清理。不能只换 MCU 就说已支持大文件。
6. Mac 应用需增加 Bulk 传输适配。Windows 组件仍是后续软件工作，硬件接口可规划跨平台，不代表 Windows 功能已完成。

验收建议：同时传 ≥4 GiB 文件、连续拖选、滚动、输入、双向边缘返回；覆盖接收端停读、慢盘、取消、USB 复位/拔线/睡眠、安装资源读取。记录负载新增输入延迟 p99（目标 ≤5 ms）和最大值、松键丢失数、返回耗时及端到端哈希。**本轮这些指标均未实测。**

## 6. 下一阶段判断

继续单 V407 路线有价值，但先不进入 PCB 投产：
1. 确认 VET6 1,050 颗供期和实际含税成交价；WEU6 作有条件备选。
2. 找可接受的 C 公头装配工艺，核实能否保留单面低价生产；必要时换公头型号，而不是把后焊费用漏掉。
